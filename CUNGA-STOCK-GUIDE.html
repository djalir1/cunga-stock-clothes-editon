System Overview & Roles

Cunga Stock is a school inventory management system. It tracks warehouse stock, student uniform issuances, and items temporarily lent to teachers. Two user roles control what each person can do.

User Roles

Feature Storekeeper Supervisor (View Only)
View all stock & data✓✓
Add / delete stock items✓✗
Issue & restock items✓✗
Issue uniforms✓✗
Manage temporary loans✓✗
Export PDF & CSV reports✓✓
View History / Activity Log✓✓

When logged in as a Supervisor, the system shows a View Only badge and hides all write/edit controls.

Login URL: Deploy URL on Vercel. All new users are automatically assigned the Storekeeper role by the database trigger. To make someone a Supervisor, change their role in the Supabase user_roles table.

Stock Inventory — What's New

🆕 Custom Low-Stock Threshold (per item)

When adding a new stock item, you can now set the Low Stock Threshold — the quantity at which the system flags the item as "Low Stock". Previously this was fixed at 5 for everything.

1
Go to Stock Items in the sidebar.
2
Click Add Item (Storekeeper only).
3
Fill in Item Name, Category, Initial Quantity.
4
Set Low Stock Threshold — e.g. enter 10 to flag the item when fewer than 10 remain.
5
Click Save Item. The system will automatically show Low Stock when quantity drops below your threshold.

🆕 Recipient Name When Issuing Stock

When issuing a stock item (pressing the – button on any row), you now enter a recipient name. This gets stored in the movement history so you can always trace who received what.

1
Click the minus (–) button on any stock item row.
2
Enter the Quantity to Issue first (top field).
3
Enter the Issued To (Name) below it. Letters only — numbers are blocked automatically.
4
Click Confirm Issue.

The recipient name then appears in History → Stock Movements as a blue "Issued to: Name" tag, and in the Reports page under the "Issued To" column.

🆕 Category Badges with Color Dots

Category badges in the stock table now show a colored dot matching the category color for clearer alignment at a glance.

Columns in Stock Table

ColumnMeaning
Total AddedCumulative total ever added to this item (including restocks).
RemainingCurrent available quantity in the warehouse.
IssuedTotal quantity issued out so far (does not decrease on restock).
StatusIn Stock / Low Stock / Out of Stock — set automatically.

Uniform Management & Sweater Numbers

Found under Uniform Inventory in the sidebar. Manages student uniform issuances separately from the main stock.

Basic Flow

1
Inventory tab: Add uniform items (e.g. "Grey Sweater Size M", quantity 50) and categories (e.g. "Sweater", "Shirt", "Trousers").
2
Issue Uniform tab: Select the uniform, enter student name, quantity, and date. Click Confirm.
3
Issued Records: See all issuances, edit records, or delete.
4
Reports tab: Filter by date range and download a professional PDF.

🆕 Sweater Number Tracking

When a uniform item belongs to a category that includes the word "Sweater" in its name, the issuance form automatically shows a required Sweater Number field.

Why? Each school sweater has a unique number sewn in. Recording it at issuance means when a sweater is found/lost, you can immediately look up who it belongs to.
1
Make sure the uniform category name contains the word "Sweater" (e.g. Sweater, School Sweater, Sweater Size L).
2
When issuing a sweater item, a # Sweater Number * field appears — enter the number (e.g. 231).
3
The system prevents duplicate sweater numbers — issuing the same number twice gives an error.
4
The Issued Records table shows a #231 badge in the Sweater # column for all sweater rows.
5
For sweaters already given before this feature was added: click the Edit (pencil) icon on any existing sweater record → enter the sweater number in the edit dialog → Save.
Database requirement: The sweater_number column must be added to the uniform_issuances table before this works. See Section 8 for the SQL.

Temporary Stock (Teacher Lending)

Found under Temporary Stock in the sidebar. A completely independent module — does not affect the main stock inventory, uniforms, or any other data. Used to track items temporarily lent to teachers (rulers, calculators, scissors, etc.).

📦

Inventory Tab

Add lendable items (name, description, quantity). Shows Total / Available / Out counts per item. Click "Lend" on any item to issue it.

⏱️

Active Loans Tab

All items currently out with teachers. Overdue items highlight in amber with "X days overdue" tag. Click "Returned" when the teacher brings it back.

✅

History Tab

Full log of returned items with the actual return date recorded.

📊

Reports Tab

Filter by date range. Export the full lending report as PDF (with Cunga Stock branding) or CSV.

How to Add a Lendable Item

1
Go to Temporary Stock in the sidebar.
2
Click Add Item.
3
Enter Item Name (e.g. "30cm Ruler"), optional Description, and Total Quantity (how many of this item are available to lend).
4
Click Add Item. It now appears in the Inventory table.

How to Lend an Item to a Teacher

1
In the Inventory tab, find the item and click the Lend button on that row. (Button is disabled if quantity is 0.)
2
Fill in: Teacher Name *, Department/Subject, Quantity to lend, Date Borrowed, Expected Return Date, Notes.
3
Click Confirm Lending. The available quantity decrements immediately.

How to Mark an Item as Returned

1
Go to the Active Loans tab.
2
Find the record and click the green Returned button.
3
Confirm. Today's date is recorded as the return date and the item quantity is restored.
Database requirement: Tables temp_stock_items and temp_stock_loans must be created in Supabase. See Section 8 for the SQL. After running, reload the schema cache: Supabase Dashboard → Settings → API → Reload schema cache.

Database Setup (Supabase SQL)

The following SQL is also saved in the project at:
supabase/migrations/20260724120000_add_sweater_numbers_and_temp_stock.sql

Copy and paste this into Supabase Dashboard → SQL Editor → New query and click Run:

-- 1. Add total_added and issued to stock_items (if missing) ALTER TABLE public.stock_items ADD COLUMN IF NOT EXISTS total_added INTEGER NOT NULL DEFAULT 0; ALTER TABLE public.stock_items ADD COLUMN IF NOT EXISTS issued INTEGER NOT NULL DEFAULT 0; -- 2. Uniform system tables (safe - uses IF NOT EXISTS) CREATE TABLE IF NOT EXISTS public.uniform_categories ( id UUID PRIMARY KEY DEFAULT gen_random_uuid(), name TEXT NOT NULL UNIQUE, created_at TIMESTAMPTZ DEFAULT now() NOT NULL ); CREATE TABLE IF NOT EXISTS public.uniform_items ( id UUID PRIMARY KEY DEFAULT gen_random_uuid(), name TEXT NOT NULL, category TEXT NOT NULL DEFAULT 'Uncategorized', total_quantity INTEGER NOT NULL DEFAULT 0, remaining_quantity INTEGER NOT NULL DEFAULT 0, created_at TIMESTAMPTZ DEFAULT now() NOT NULL, updated_at TIMESTAMPTZ DEFAULT now() NOT NULL ); CREATE TABLE IF NOT EXISTS public.uniform_issuances ( id UUID PRIMARY KEY DEFAULT gen_random_uuid(), uniform_id UUID REFERENCES public.uniform_items(id) ON DELETE CASCADE NOT NULL, student_name TEXT NOT NULL, quantity_taken INTEGER NOT NULL DEFAULT 1, issue_date DATE NOT NULL DEFAULT CURRENT_DATE, created_at TIMESTAMPTZ DEFAULT now() NOT NULL ); -- 3. Sweater number column (Feature: track sweater numbers) ALTER TABLE public.uniform_issuances ADD COLUMN IF NOT EXISTS sweater_number TEXT; -- 4. Temporary Stock tables (Feature: teacher lending) CREATE TABLE IF NOT EXISTS public.temp_stock_items ( id UUID PRIMARY KEY DEFAULT gen_random_uuid(), name TEXT NOT NULL, description TEXT, total_quantity INTEGER NOT NULL DEFAULT 1, available_quantity INTEGER NOT NULL DEFAULT 1, created_at TIMESTAMPTZ DEFAULT now() NOT NULL, updated_at TIMESTAMPTZ DEFAULT now() NOT NULL ); CREATE TABLE IF NOT EXISTS public.temp_stock_loans ( id UUID PRIMARY KEY DEFAULT gen_random_uuid(), item_id UUID NOT NULL REFERENCES public.temp_stock_items(id) ON DELETE CASCADE, teacher_name TEXT NOT NULL, department TEXT, quantity INTEGER NOT NULL DEFAULT 1, borrowed_date DATE NOT NULL DEFAULT CURRENT_DATE, expected_return_date DATE, actual_return_date DATE, status TEXT NOT NULL DEFAULT 'borrowed', notes TEXT, created_at TIMESTAMPTZ DEFAULT now() NOT NULL, updated_at TIMESTAMPTZ DEFAULT now() NOT NULL ); -- 5. Enable RLS + policies on all new tables ALTER TABLE public.uniform_categories ENABLE ROW LEVEL SECURITY; ALTER TABLE public.uniform_items ENABLE ROW LEVEL SECURITY; ALTER TABLE public.uniform_issuances ENABLE ROW LEVEL SECURITY; ALTER TABLE public.temp_stock_items ENABLE ROW LEVEL SECURITY; ALTER TABLE public.temp_stock_loans ENABLE ROW LEVEL SECURITY; CREATE POLICY IF NOT EXISTS "auth_uniform_categories" ON public.uniform_categories FOR ALL TO authenticated USING(true) WITH CHECK(true); CREATE POLICY IF NOT EXISTS "auth_uniform_items" ON public.uniform_items FOR ALL TO authenticated USING(true) WITH CHECK(true); CREATE POLICY IF NOT EXISTS "auth_uniform_issuances" ON public.uniform_issuances FOR ALL TO authenticated USING(true) WITH CHECK(true); CREATE POLICY IF NOT EXISTS "auth_temp_stock_items" ON public.temp_stock_items FOR ALL TO authenticated USING(true) WITH CHECK(true); CREATE POLICY IF NOT EXISTS "auth_temp_stock_loans" ON public.temp_stock_loans FOR ALL TO authenticated USING(true) WITH CHECK(true);
After running the SQL: Go to Supabase Dashboard → Settings (⚙️) → API → scroll down → click "Reload schema cache". Wait 10 seconds, then refresh the app. This is required every time you add new tables.
